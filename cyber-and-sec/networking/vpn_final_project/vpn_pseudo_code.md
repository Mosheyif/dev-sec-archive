

**Phase 1: System-Level Configuration & Routing**

* **Server Routing Setup:** Enable OS-level IP forwarding. Configure NAT (Masquerade) to translate traffic exiting the virtual network out to the public internet.
* **Client Routing Setup:** Modify the local OS routing table to direct intended outbound traffic (or all default traffic) into the newly created virtual interface, rather than the physical network interface.

**Phase 2: Data Structures & State Management (UDP Specifics)**

* **Client Registry (Server-side):** Since UDP is connectionless, create a dynamic data structure to track active clients. This registry must map the client's external public IP and UDP port to their assigned internal Virtual IP, their specific encryption keys, their authentication status, and a "last seen" timestamp.

**Phase 3: Initialization & The Authentication Handshake**

* **Interface & Socket Allocation:**
* Both Server and Client allocate a Layer 3 virtual network interface (TUN) to capture and inject raw IP packets.
* Server binds a UDP socket to a specific listening port. Client initializes a UDP socket aimed at the Server.


* **Authentication Sequence:**
* Client crafts an authentication payload (containing credentials or a token), encrypts it, and sends it to the Server via UDP.
* Server receives the datagram, attempts decryption, and validates the credentials.
* If valid, the Server adds the client to the Client Registry, allocates a Virtual IP, and sends an encrypted acknowledgment back to the Client. If invalid, the packet is silently dropped to prevent DoS attacks.



**Phase 4: The Forwarding Engine (Main Event Loop)**

* Both applications enter an I/O multiplexing loop, monitoring the TUN interface and the UDP socket simultaneously without blocking.
* **Outbound Flow (Client OS $\rightarrow$ Server $\rightarrow$ Internet):**
1. Client reads a raw IP packet generated by the local OS from the TUN interface.
2. Client encrypts the entire IP packet and sends it as a payload via UDP to the Server.
3. Server receives the UDP datagram. It verifies the source IP/Port against the Client Registry.
4. If authenticated, Server decrypts the payload to reveal the original raw IP packet.
5. Server writes the raw IP packet into its own TUN interface. The Server's OS routing takes over and forwards it to the internet.


* **Inbound Flow (Internet $\rightarrow$ Server $\rightarrow$ Client OS):**
1. Server's OS receives returning traffic and routes it into the Server's TUN interface.
2. Server reads the raw IP packet from the TUN interface.
3. Server extracts the destination IP address from the packet header (which is the Virtual IP of the target client).
4. Server looks up the Virtual IP in the Client Registry to find the matching external UDP IP/Port and encryption keys.
5. Server encrypts the packet and sends it via UDP to the specific client.
6. Client receives the UDP datagram, decrypts it, and writes the raw IP packet into its local TUN interface for the OS to process.



**Phase 5: Connection Maintenance (Reliability over UDP)**

* **Keep-Alive Mechanism:** Clients periodically send lightweight, encrypted "ping" packets to the Server to keep NAT mappings open on public routers and prove they are still active.
* **Timeout Purging:** The Server constantly evaluates the Client Registry. If a client has not sent any data or keep-alive packets within a defined timeout threshold, the Server removes them from the registry and frees their Virtual IP.
